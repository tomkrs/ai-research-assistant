## 2026-05-27 — Initial literature search tool setup

**What was done:**
- Created `code/search.py`: automated literature search script with CLI interface
- Created `code/requirements.txt`: `requests`, `biopython`, `arxiv`
- Created `code/.venv`: Python 3.10 virtual environment with all dependencies installed
- Created `CLAUDE.md`: project rules for venv usage and session history

**Key decisions:**

- Deduplication by DOI first, then by title prefix (first 120 chars, lowercased)
- Single flat CSV output with all available metadata fields; `found_by_query` column preserved for PRISMA traceability
- `--email` flag required for NCBI Entrez API terms of service compliance

## 2026-06-01 — Topic template and search filters (date, citations)

**What was done:**
- Created `topic_template.md` at project root: markdown file with YAML frontmatter for
  search parameters and prose sections with guiding questions (research question,
  background, population, intervention, outcomes, key terms, exclusions, study designs)
- Updated `code/search.py`:
  - Added `parse_template()`: splits YAML frontmatter from prose, strips HTML comments
    and section headings, returns `(params_dict, clean_prose)`
  - Added 3-tier config resolution: CLI args > template YAML > hardcoded defaults;
    all argparse defaults set to `None` to detect explicit overrides
  - Added `--template` flag; `--topic` overrides template prose if both given
  - Added `--date-from` / `--date-to`: applied natively to PubMed (`[dp]` filter),
    Semantic Scholar (`year` API param), arXiv (post-fetch year filter)
  - Added `--min-citations`: post-collection filter; papers without citation data are
    kept (only Semantic Scholar provides counts)
  - Added `pyyaml` dependency; installed into `code/.venv`; added to `requirements.txt`
  - Updated `save_search_info()` to include date range and min-citations in settings table

**Key decisions:**
- YAML frontmatter chosen for template parameters (standard, human-readable, easy to parse)
- min-citations filter keeps papers without citation data rather than dropping them,
  since PubMed and arXiv don't expose citation counts — filter is additive, not exclusive
- arXiv date filtering done post-fetch (client has no native range param); fetch budget
  multiplied by 3 when a date range is active to compensate for filtered-out results

**Next steps / open items:**
- Test a real search run end-to-end with a filled template
- Add auto-summarization of abstracts (via Ollama)
- Add PRISMA-style include/exclude filtering step

## 2026-06-01 — Paper screening script (screen.py)

**What was done:**
- Created `code/screen.py`: LLM-based paper screening script
  - Reads title + abstract from a search results CSV
  - Sends each paper to Ollama with inclusion/exclusion criteria and free-text instructions
  - Appends 5 new columns: `screen_decision`, `screen_inclusion_reason`,
    `screen_exclusion_reason`, `screen_confidence`, `screen_model`
  - Saves progress every N papers (default 10) to survive interruptions
  - Resume mode: skips rows that already have a `screen_decision`
  - Saves `screen_info.md` alongside the output with criteria and decision summary
  - Default model: `gemma4:e4b`
- Created `utils/screen_template.md`: criteria template with YAML frontmatter
  (model, input_csv, output_csv, save_every) and sections for topic context,
  inclusion criteria, exclusion criteria, and additional instructions
- Updated `README.md`: added Step 2 screening section, screen.py CLI table,
  updated output structure, status table, and project structure

**Key decisions:**
- `uncertain` is the safe fallback for LLM parse failures — never silently drops papers
- `screen_model` column stored per row so mixed-model screening runs are fully traceable
- Template sections parsed by `## Heading` — users can freely add or remove sections

**Next steps / open items:**
- Test screening run end-to-end
- Add abstract auto-summarization script
- Add PRISMA flow export
